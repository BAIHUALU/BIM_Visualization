# 开发进度说明：计划/实际双视口联动 V3

## 本次版本目标

本次版本将大屏中心 BIM 展示从单视口颜色编码改为上下双视口同步对比：

- 上方视口显示计划进度，按时间轴日期计算计划状态并变色。
- 下方视口显示实际进度，按后台录入完成率变色。
- 两个视口保持相机、筛选和选中构件同步。
- 实际视口中已完成构件使用轻量方块替代，以降低浏览器渲染压力。

后端技术栈暂不迁移 Java，本次继续沿用现有 Flask API，避免展示大改和技术栈迁移同时扩大风险。

## 已完成成果

- `App.vue` 已接入两个 `BimViewer` 实例，分别作为计划视口和实际视口。
- 双视口共享当前日期、区域筛选、分类筛选、选中构件和相机状态。
- 任一视口点击构件后，右侧构件信息面板会更新，另一个视口同步高亮同一构件。
- 任一视口旋转、缩放、平移后，另一个视口通过 `camera-change` 和 `syncCameraState` 同步视角。
- 计划视口保留原有计划状态颜色：未开始、施工中、计划完成、无计划。
- 实际视口新增实际状态颜色：未录入、实际未开始、实际施工中、实际完成。
- 实际视口中 `actual_percent >= 100` 且存在中心点信息的构件，会隐藏真实几何并改用 `InstancedMesh(BoxGeometry)` 方块显示。
- 未完成、进行中、未录入构件继续使用真实 processed geometry，保留可检查的 BIM 细节。
- 构建验证已通过：`npm run build`。

## 问题与策略

- 问题：单视口用复杂颜色编码同时表达计划、实际和偏差，用户理解成本高。
  策略：改为上下双窗口，计划和实际各自独立表达，偏差继续放在图表和重点关注列表中。

- 问题：完整 BIM 几何在大屏端渲染压力较高。
  策略：只在实际视口中对已完成构件做轻量方块替代，未完成构件保留真实几何，兼顾流畅度和定位检查。

- 问题：两个 Three.js 视口容易出现视角漂移。
  策略：父组件集中保存相机状态，每个视口只响应来自另一个视口的同步事件，避免循环更新。

- 问题：processed geometry manifest 中组件元数据不一定包含中心点或包围盒。
  策略：优先从 `modelBlocks.meshes` 查找 `center/bbox`；缺少中心点时回退真实几何，不强行替代。

## 当前限制与后续建议

- 当前轻量化只替代实际视口中的已完成构件，计划视口仍显示真实几何。
- 已完成方块用于宏观进度对比，不保留完整构件外形细节。
- 如果后续需要进一步降压，可以按区域或板块合并 completed 方块，或增加“精细/大屏”模式切换。
- Java 后端迁移建议单独立项：先保持 `/api/model-blocks`、`/api/block-schedule`、`/api/actual-progress` 接口返回结构不变，再替换服务实现。

## 2026-05-06 领导大屏精简版

本次调整将首页从“分析后台信息密集型”继续收敛为“领导大屏重点展示型”：

- 左侧只保留两张核心图表：区域完成对比、滞后区域排行。
- 右侧只保留重点风险板块，并在同一个面板内压缩显示实际录入、计划完成、实际完成、预警/滞后四个关键指标。
- 删除首页上的区域录入覆盖率图表和偏差分布环图，避免两侧图表过多导致主视口被分散注意力。
- 区域完成对比只展示差异较大的关键区域；滞后区域排行只展示负偏差最明显的区域，减少标签拥挤。
- 风险列表改为暗色细滚动条，避免截图中出现突兀的原生白色滚动条。
- 实际视口中的已完成轻量方块改为更亮的绿色，尺寸提高，并增加轻微发光效果，让领导能更直观看出“实际已完成部分”。

后续建议：如果还需要覆盖率、偏差分布、完整区域排行等分析能力，建议单独增加“详细分析模式”或二级页面，不再堆回大屏首页。当前首页优先服务快速汇报：模型对比第一，风险板块第二，图表辅助第三。

## 2026-05-06 模型压缩与高帧率渲染优化

当前已有压缩/降载策略：

- 源模型 `Airport1.glb` 使用 Draco 压缩，体积约 191MB。
- 前端运行时优先加载离线生成的 processed geometry cache，避免浏览器每次打开都解 Draco。
- 预处理阶段使用 `meshoptimizer` 简化 primitive，默认每个 primitive 最多 120 个三角面。
- 运行时按 chunk 合并 BufferGeometry，顶点携带 `componentId`，颜色和显隐通过 GPU 颜色纹理更新。
- 时间轴、筛选、选中高亮不重建模型，只更新颜色/可见性状态。

本次新增状态驱动 LOD：

- 实际进度视口中，`actual_percent >= 100` 的已完成板块不再逐构件显示真实几何。
- 已完成构件按 `block_id` 聚合，使用 `modelBlocks.meshes` 中的 `bbox_min/bbox_max` 计算一个板块级粗包围盒。
- 每个已完成板块只渲染一个 `InstancedMesh(BoxGeometry)` 实例，状态栏显示“板块盒数量”和“隐藏构件数量”。
- 缺少 bbox 的已完成构件回退真实几何，避免因为数据不完整导致构件消失。
- 未完成、未录入、进行中以及风险板块继续显示真实 processed geometry，保证甲方能检查重点问题区域。

限制说明：本次优化仍基于现有 chunk 几何缓存，已完成构件通过颜色纹理隐藏，不改变缓存文件结构；它能明显减少屏幕上的复杂可见形体和完成构件实例数量，但不会从网络层彻底避免下载 processed chunk。后续如需继续提高加载速度，可追加“按状态/区域生成独立轻量缓存”或“风险 chunk 懒加载”。

## 2026-05-06 标段级加载与进度分析页

本次大版本将系统从“单个全场大屏”扩展为“标段级进度工作台”，并新增独立进度分析页面。

### 标段划分

- E 标段：`zone` 以 `E` 开头的区域，即 `E1-E13`。
- W 标段：`zone` 以 `W` 开头的区域，即 `W1-W6`。
- URL 无 `section` 参数时默认进入 E 标段。
- 标段切换后会清空当前选中构件和筛选状态，避免旧标段的选中信息残留到新标段。

### 页面路由

- `/`：整体进度页面，沿用当前计划/实际双视口大屏。
- `/analysis`：进度分析页面，上部显示当前标段模型，下部显示自动生成的进度分析报告。
- 两个页面通过 query 共享当前标段，例如 `/?section=E`、`/analysis?section=W`。
- 页面顶部新增“整体进度 / 进度分析”入口和“E 标段 / W 标段”切换控件。

### 标段模型缓存

预处理脚本 `scripts/preprocess-geometry-cache.mjs` 已扩展为同时生成全量缓存和标段缓存：

- `public/models/processed/geometry_manifest.json`
- `public/models/processed/sections/E/geometry_manifest.json`
- `public/models/processed/sections/W/geometry_manifest.json`

当前生成结果：

- E 标段：12581 个构件，35 个 geometry chunk。
- W 标段：8866 个构件，29 个 geometry chunk。

`BimViewer` 新增 `section-code` 参数，优先加载对应标段缓存；如果标段缓存缺失，会回退到原全量 processed cache，再由前端按标段数据过滤，避免页面空白。

### 统计与报告逻辑

- 首页左侧图表、右侧重点风险板块、模型视口、后台录入筛选都只统计当前标段。
- 进度分析页复用当前计划、实际录入和模型块数据，在前端自动生成报告。
- 报告包含计划完成率、实际完成率、录入覆盖率、主要滞后区域、重点风险板块和核查建议。
- 分析页模型采用实际进度视图和状态驱动 LOD，已完成板块继续使用粗包围盒，未完成和风险区域保留真实几何。

### 后续建议

- 当前报告为前端自动生成，适合第一版交付演示；如甲方需要正式周报/月报，可后续增加后端报告保存和人工编辑接口。
- 如果未来直接部署到静态服务器，`vue-router` 的 history 模式需要服务器将 `/analysis` 等路径回退到 `index.html`。
- Java 后端迁移仍建议单独立项；本版未改变 `/api/model-blocks`、`/api/block-schedule`、`/api/actual-progress` 接口结构。
